## 一、先客观说一句

这个技能**写得相当成熟**,覆盖面比脑洞补丁那个完善太多:
- 两阶段工作流清晰(先标题后正文)
- 第一人称角色沉浸讲得透(4 个内部问题 + 6 种沉浸手法 + 硬规则 + 反失败模式)
- 开头钩子 5 种类型 + 具体示例
- 节奏、密度、转场、金句、对比、情绪曲线全覆盖
- 去AI技巧实用(删虚词 / 真实感受替大道理 / 细节替概括 / 留白句式)
- 禁用清单明确
- 有体裁适配意识
- Final QA 完整

但**成熟过头了**。问题不在"缺什么",而在"太多太全,没有分层"。这跟脑洞补丁是两个极端:
- 脑洞补丁:规则太少、太模糊 → 产出差
- wechat-idea-writer:规则太多、太全 → 认知超载,产出"合规但没灵魂"

## 二、文章产出层面的问题(从规则推断)

由于没有示例文章,以下是根据规则设计推断出的产出问题:

### 问题 1:容易写出"技巧堆砌"的文章
AI 会试图把钩子 + 骨架 + 金句 + 对比 + 情绪曲线都用上,500 字的精简文塞进太多技巧,显得刻意。读者感受到的是"作者在炫技",不是"一个人在说话"。

### 问题 2:第一人称沉浸容易过度
角色沉浸占了 SKILL.md 约 40% 篇幅(4 个内部问题 + 6 种手法 + 硬规则 + 反失败模式)。AI 会每篇都强行编一个"28 岁设计师""35 岁刚被裁"的人设,即使主题是"怎么挑冰箱"这种不需要人设的干货。

### 问题 3:去AI技巧可能导致另一种生硬
"删虚词""留白句式""细节替概括"这些技巧,AI 机械执行后可能写出"每句都留白""每段都塞细节"的另一种套路。去AI去成了新的AI味。

### 问题 4:精简文套用长文结构
默认精简(500–900 字),但 Stage 2 大量规则(内容骨架、情绪曲线、对比结构)是长文专用。AI 在 500 字里也塞"分层讲解 + 避坑 + 总结",显得套路。

## 三、技能设计的根本问题(按优先级)

### P0 · 必须修(直接导致认知超载)

#### P0-1. 缺少优先级体系,313 行规则平铺
**现状**:所有规则(钩子、骨架、节奏、密度、转场、金句、对比、情绪曲线、去AI、失败模式、QA)权重相同,没有告诉 AI"哪几条最关键"。
**后果**:AI 把精力平均分配,最关键的(角色沉浸 + 开头落场景 + 去AI虚词)和次要的(金句公式 + 对比结构)被同等对待。
**修法**:在 SKILL.md 开头加一个"三条铁律"或"核心层"小节,明确最高优先级。其余技巧降级为"参考"。建议核心层只留 4 条:
```
核心铁律(每篇必做,不过不发):
1. 第一人称角色沉浸 — 我是谁、在哪个场景、心里什么矛盾
2. 开头必须落在具体场景 — 不用"如今很多人…"开头
3. 删AI虚词 — 真的/特别/非常/其实/不得不说,出现即删
4. 单个 md 代码块输出 — 无前后解释性文字
```

#### P0-2. 没有标杆范文
**现状**:只有规则,没有一篇完整的"好文章"作为对标。
**后果**:AI 没有质量基准,只能靠规则凑。规则越多,越容易写出"每条都合规但没灵魂"的文章。这是这个技能最讽刺的地方——规则最全,却最缺"什么是好"的定义。
**修法**:手写 2 篇标杆范文(1 篇精简情绪文 + 1 篇精简干货文),存入 `references/范文库.md`,每篇附"为什么这篇好"的解析(对应到核心铁律)。AI 写稿前先默读范文找感觉。

#### P0-3. 精简 / 长文规则没有分层
**现状**:默认精简(500–900 字),但 Stage 2 的"内容类型骨架""情绪曲线设计""对比结构""场景转换技巧"都是长文专用,没有标注。
**后果**:AI 在 500 字精简文里也套用"痛点引入 → 分层讲解 → 避坑指南 → 总结互动"的长文结构。
**修法**:Stage 2 明确分两档:
```
精简模式(默认,500–900字)只做3件事:
  1开头场景(2-3句) + 1正文(核心观点+1个细节) + 1收尾画面(1句)
  禁用:内容骨架、情绪曲线、对比结构、多级标题
  至多1种Markdown强调

长文模式(1500–2500字,用户明确要求时):
  启用全部结构技巧(内容骨架/情绪曲线/对比/转场)
  至少3种Markdown强调
```

### P1 · 建议修(影响规则效率)

#### P1-1. 规则冗余,需要去重
以下内容在多处重复定义:
- "去AI感技巧"的"删无效虚词" ↔ Final QA 的"不包含真的/特别/非常" ↔ Banned Phrases 的禁用清单 → **三处重叠**
- "节奏控制"的"轻重交替" ↔ "信息密度"的"密度要有 cycle" → **概念重叠**
- "反第三人称失败模式"6 种 ↔ "Perspective and Empathy"的 Hard rules → **重叠**
- "Write Like a Human Editor" ↔ "De-AI Techniques" ↔ "Perspective and Empathy" → **三处都在讲"像人写"**

**修法**:合并同类项,每个原则只在一处定义。去AI相关合并为一节,节奏/密度合并为一节,角色沉浸相关合并为一节。

#### P1-2. Final QA 15 条无优先级
**现状**:15 条自检平铺,AI 为了过自检把精力平均分配。
**修法**:分三档:
```
P0(不过则不发,3条):
  - 只有一个md代码块,无前后解释
  - 第一段落在具体场景,不在概括
  - 无AI虚词(真的/其实/非常/不得不说)

P1(应该过,5条):
  - 第一人称沉浸,有角色和矛盾
  - 无禁用模板词(写在最后/总之/综上所述)
  - 无三连续段落做同一件事
  - 至少一个沉浸瞬间(犹豫/自嘲/嘴上vs心里)
  - 结尾是具体画面,不是口号

P2(尽量过,7条):
  - 其余格式、密度、转场相关
```

#### P1-3. 标题生成过度依赖句式模板
**现状**:`title-patterns.md` 给了 10 类 × 4 个 = 40 个句式模板。
**问题**:AI 容易"填空式"造标题,产出"像标题但没灵魂"的句子。模板填空 ≠ 好标题。
**修法**:在模板前加"好标题的 4 个本质标准",模板降级为"灵感库":
```
好标题的4个本质(生成时自检,不达标不输出):
1. 具体性 — 有具体的人/事/物,不是空泛概念
2. 意外性 — 打破读者的某个预设
3. 相关性 — 读者能立刻觉得"跟我有关"
4. 情绪张力 — 让人想点开看个究竟

句式模板只是灵感,不是填空格。先想"这4个本质怎么满足",再参考句式。
```

#### P1-4. 第一人称沉浸过度强化
**现状**:角色沉浸占 SKILL.md 约 40% 篇幅,且被设为"hard default"。
**问题**:不是所有公众号文章都适合第一人称沉浸。科普、资讯、观点评论、产品种草不一定需要"28 岁设计师"人设。虽然 Genre Adaptation 提了养生科普用趣味口吻,但权重不够,AI 仍会默认套角色沉浸。
**修法**:把"第一人称沉浸"从"全局默认"降为"情绪文/反思文的默认"。在"写作前定调"步骤里先判体裁,再定口吻。

### P2 · 可以优化(长期完善)

#### P2-1. 体裁适配不全
**现状**:只覆盖个人情绪、养生科普、干货教程、新闻。
**缺失**:观点评论、故事叙事、产品种草、活动宣传、盘点合集。
**修法**:补全常见体裁的口吻和结构指引,每种给 1 个开头示例。

#### P2-2. 缺少"写作前定调"步骤
**现状**:直接进入"怎么写",没有"先判断体裁 → 确定读者 → 确定核心情绪 → 选钩子"的定调环节。
**修法**:Stage 2 开头加一个"30 秒定调"步骤(内部执行,不输出):
```
写前定调(内部,不输出):
1. 这篇是什么体裁?(情绪/干货/科普/观点/故事/种草)
2. 读者是谁?他们正在经历什么?
3. 核心情绪是什么?(共鸣/好奇/释然/警醒)
4. 用哪种钩子?(痛点/悬念/数据/反常理/提问)
5. 用第几人称?(情绪文默认我,科普默认趣味口吻)
定调后再写,不要边写边定。
```

#### P2-3. 缺少改稿指导
**现状**:只有"怎么写初稿"和"Final QA 检查清单",没有"怎么改"。
**修法**:加一个"初稿 → 自检 → 定位问题 → 针对性改"的循环:
```
改稿循环:
1. 初稿写完,读一遍Final QA的P0(3条),不过直接改
2. 再读一遍P1(5条),定位哪条没过
3. 针对没过的那条,只改那一处,不要重写全文
4. 改完再读一遍开头300字,确认钩子还在
```

#### P2-4. Markdown 格式要求可能引导花哨
**现状**:"至少 3 种强调格式"在 500 字精简文里容易显得花哨。
**修法**:改为"精简文至少 1 种,长文至少 3 种,不强求数量,自然优先"。

#### P2-5. 参考层技巧应外移
**现状**:金句公式、对比结构、情绪曲线、场景转场等"高级技巧"都堆在 SKILL.md 里。
**修法**:移到 `references/` 目录,按需调用:
```
references/
├── 范文库.md          ← 2篇标杆范文+解析(P0)
├── 标题句式库.md      ← 现有title-patterns.md
├── 金句与结构库.md    ← 金句公式+对比结构+情绪曲线
└── 去AI技巧库.md      ← 删虚词+留白句式+细节替概括
```
SKILL.md 只保留"何时该查哪个 reference"的索引。

## 五、一句话总结

> 这个技能不是"不够好",而是"好东西太多没分层"。
> 313 行规则平铺给 AI,等于没规则——AI 抓不住重点,要么全用(技巧堆砌),要么乱用(顾此失彼)。
> 把"核心铁律 4 条"拎出来放最前面,详细技巧移到 references 按需调用,加 2 篇标杆范文定基准,这个技能会从"技巧大全"变成"真正能写出好文章的引擎"。
